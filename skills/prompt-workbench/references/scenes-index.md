# 场景索引

> 本文件由 `npm run build:skills` 从场景数据生成，不要手改。

| id | 场景 | 分类 | 什么时候用 | 问题数 |
| --- | --- | --- | --- | --- |
| `requirement-clarify` | 把模糊需求说清楚 | 需求 | 脑子里有个想法但说不清要做成什么样；或者别人只给你一句话，你不知道从哪开始。 | 5 |
| `coding-task` | 把任务变成 AI 能执行的开发任务 | 开发 | 要把一个开发任务交给 AI 写代码，但说太粗它乱改、说太细自己又费劲。 | 5 |
| `document-writing` | 把一句话要求变成写作提示词 | 写作 | 要写报告、总结、通知、文案，但直接丢给 AI 得到的东西又空又套话。 | 5 |
| `debug` | 报错了，帮我定位 | 开发 | 代码跑不起来、报错看不懂、或者行为和你预期不一样，卡了半小时以上。 | 5 |
| `code-review` | 帮我审这段代码 | 开发 | 写完一段代码不确定质量，或者合并前想让人挑一遍问题。 | 4 |
| `refactor-plan` | 这段代码该重构了，给我一个计划 | 开发 | 代码越改越难受、加个功能要动五个地方、或者想整理但不敢动。 | 5 |
| `test-design` | 帮我想测试用例 | 开发 | 功能写完了不知道怎么测，怕漏掉边界；或者要给别人的代码补测试。 | 4 |
| `api-integration` | 要对接一个第三方 API，怎么开始 | 开发 | 要接支付、地图、AI、短信、开放平台等外部接口，文档看着头大。 | 4 |
| `code-explain` | 让 AI 把这段代码讲清楚 | 开发 | 接手别人的代码、看开源项目源码、或者自己以前写的代码看不懂了。 | 4 |
| `bug-report` | 把这个 bug 写成能复现的 issue | 开发 | 要提 issue / 向别人报障 / 交给 AI 修，但你现在只会说「它坏了」。 | 5 |
| `perf-opt` | 它太慢了，怎么优化 | 开发 | 页面加载慢、接口返回慢、数据一多就卡，但不知道瓶颈在哪。 | 4 |
| `security-check` | 帮我做一次安全自查 | 开发 | 项目要公开、要给同学/客户用、或者代码里有 key 和用户数据。 | 4 |
| `deploy-ci` | 把这个项目部署上线（带自动测试） | 开发 | 本地能跑，但不知道怎么发布到网上；或者每次发布都手动，容易漏。 | 4 |
| `tech-select` | 这个技术选型，帮我做决定 | 开发 | 在两个库/框架/方案之间纠结，怕选了之后回不了头。 | 4 |
| `data-analysis` | 这堆数据，帮我分析出结论 | 数据 | 手上有表格/日志/问卷数据，想知道它说明了什么，但不想只贴个平均数。 | 4 |
| `research-compare` | 帮我调研这几个东西，给个结论 | 调研 | 要调研新技术/竞品/方案，但不想看完 20 篇文章还不知道结论。 | 4 |
| `learn-tech` | 帮我排一个学新技术的计划 | 学习 | 想学一个新东西（语言/框架/工具），但一打开教程就迷路，学完又不会用。 | 4 |
| `agent-task` | 把这个任务交给 AI Agent 去执行 | 开发 | 想让编码 Agent（CodeBuddy / Cursor / Claude Code 等）帮你做一件完整的事，但怕它乱改。 | 5 |
| `tech-doc` | 帮我写技术文档 / README | 写作 | 项目要给人看，但没有 README；或者要写设计文档、接口文档、周报。 | 4 |
| `meta-prompt` | 把我的任务变成一段提示词 | 提示词 | 你要让 AI 做一件具体的事，但不知道该怎么开口，或者以前问过效果很一般。 | 4 |

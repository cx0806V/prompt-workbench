# 要对接一个第三方 API，怎么开始

- **id**：`api-integration`
- **分类**：开发
- **什么时候用**：要接支付、地图、AI、短信、开放平台等外部接口，文档看着头大。
- **关键词**：api、对接、接口、第三方、sdk、鉴权、token、webhook

## 问题清单（按顺序，一次只问一个）

1. `target`（必填）：要对接哪个服务？把文档链接或关键字段贴上来。
   - 为什么问：不同服务的鉴权和错误码差异很大，不能靠常识。
   - 示例回答：DeepSeek API（OpenAI 兼容），要调 chat/completions
2. `need`（必填）：你要完成什么业务流程？用户做什么、你调几次接口、最后得到什么。
   - 为什么问：接口文档是零件，业务流程才是你要的东西。
   - 示例回答：用户点「生成」，我调一次接口，把结果存到本地并显示
3. `constraint`（必填）：有什么限制？免费额度、请求频率、不能在浏览器暴露 key、必须后端代理。
   - 为什么问：安全和成本问题必须在写代码之前定。
   - 示例回答：纯前端项目，key 不能暴露，所以可能需要代理
4. `fail`（可选）：失败了怎么办？重试几次、给用户看什么、要不要降级。
   - 为什么问：外部接口一定会失败，处理方式决定用户体验。
   - 示例回答：失败就提示重试，最多 2 次，不要自动扣费

## 模板（把 {{key}} 替换成用户回答原文）

````text
你是一位做过很多第三方对接的后端工程师。先给方案骨架，再给代码，每一步都要能验证。

## 对接对象
{{target}}

## 业务目标
{{need}}

## 限制条件
{{constraint}}

## 失败处理
{{fail}}

## 输出要求
1. **调用链路**：用户动作 → 我的服务 → 第三方接口，画成步骤清单，标出每一步的输入输出。
2. **鉴权方案**：key 放在哪、怎么传、为什么这样安全；如果不能在客户端暴露，给出最小代理方案。
3. **最小可运行示例**：先用 curl 或伪代码验证一次请求，列出必须的字段；不要直接给完整业务代码。
4. **错误处理**：列出这个接口最常见的 3 类错误（鉴权失败 / 参数错误 / 限流），各自的处理方式。
5. **验证清单**：我按什么顺序自测，才能在不写完整功能的情况下确认接口通了。
6. 文档里我没给全的字段，标「待确认」并告诉我怎么查，不要编造。

## 禁止
- 不要编造接口字段名或错误码。
- 不要把 key 写进前端代码示例里。
````

## 交付要求

````text
## 通用交付规则（自动附加，优先级高于上面的表述）
- 如果我要的是「一个结果」（代码、程序、文案、方案、清单、报告）：**先给一版能直接用的最小版本**；缺的参数用默认假设填上并标注「假设」，不要因为信息不全就只问不产出。
- 如果我要的是「改我现有的仓库/文件/系统」：先列改动清单等我确认，再动手。
- 需要我补充的信息最多 3 条，放在结果之后，不要放在最前面。
````

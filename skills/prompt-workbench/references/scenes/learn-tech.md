# 帮我排一个学新技术的计划

- **id**：`learn-tech`
- **分类**：学习
- **什么时候用**：想学一个新东西（语言/框架/工具），但一打开教程就迷路，学完又不会用。
- **关键词**：学习、计划、入门、教程、学会、新技术、自学、路线

## 问题清单（按顺序，一次只问一个）

1. `target`（必填）：要学什么？具体到版本或具体用法。
   - 为什么问：「学 Python」和「用 Python 处理 Excel」是两件事。
   - 示例回答：学 Node + 写一个能跑的命令行工具
2. `background`（必填）：你现在已会什么？哪些相关的基础有、哪些没有。
   - 为什么问：决定从哪一层开始讲，避免重复或跳步。
   - 示例回答：会 HTML/CSS/一点 JS，没写过后端，没用过命令行
3. `time`（必填）：每天能投入多少时间？能持续多少天。
   - 为什么问：计划必须放进真实时间是可行的。
   - 示例回答：每天 1 小时，两周
4. `goal`（必填）：做到什么算学会？给一个能交付的产物。
   - 为什么问：「学会」没有标准，产物才有。
   - 示例回答：能独立写出一个读 CSV 并输出统计的命令行工具

## 模板（把 {{key}} 替换成用户回答原文）

````text
你是一位带过很多新人的工程师。请按我的真实时间和基础排计划，不要给我一堆教程链接。

## 要学的东西
{{target}}

## 我的基础
{{background}}

## 每天可投入时间 / 周期
{{time}}

## 学会的标准
{{goal}}

## 输出要求
1. **第一步先做什么**：只给一个动作，今天就能做（≤30 分钟）。
2. **阶段计划**：拆成 3–4 个阶段，每阶段包含：
   - 要解决的问题（为什么学这块）
   - 每天做什么（一天一件事，不要「看第 1–3 章」）
   - **可验证的产物**（能跑的东西 / 能输出的结果）
3. **最常见的坑**：3 条，每条给「出现什么现象就说明掉坑了」。
4. **检验方式**：怎么在不看教程的情况下，验证自己真的学会了。
5. 明确说明：哪些内容这个阶段**先不学**，为什么。

## 禁止
- 不要推荐超过 3 个资源链接。
- 不要给「7 天精通」这种不现实的安排。
- 不要把「看教程」当成一个阶段的产物。
````

## 交付要求

````text
## 通用交付规则（自动附加，优先级高于上面的表述）
- 如果我要的是「一个结果」（代码、程序、文案、方案、清单、报告）：**先给一版能直接用的最小版本**；缺的参数用默认假设填上并标注「假设」，不要因为信息不全就只问不产出。
- 如果我要的是「改我现有的仓库/文件/系统」：先列改动清单等我确认，再动手。
- 需要我补充的信息最多 3 条，放在结果之后，不要放在最前面。
````

# 报错了，帮我定位

- **id**：`debug`
- **分类**：开发
- **什么时候用**：代码跑不起来、报错看不懂、或者行为和你预期不一样，卡了半小时以上。
- **关键词**：报错、调试、bug、异常、不生效、跑不起来、crash、error

## 问题清单（按顺序，一次只问一个）

1. `symptom`（必填）：现象是什么？把报错原文/关键日志直接贴上来。
   - 为什么问：报错原文比任何转述都准。
   - 示例回答：TypeError: Cannot read properties of undefined (reading "map")，指向 app.js 第 42 行
2. `env`（必填）：运行环境和技术栈是什么？版本号、命令、在哪个系统上跑的。
   - 为什么问：同一个报错在不同版本里原因完全不同。
   - 示例回答：Node 22 + Vite 6，Windows 11，npm run dev 时出现
3. `repro`（必填）：怎么触发？能不能稳定复现？大概多久出现一次。
   - 为什么问：不能复现的问题，先要做的是缩小范围。
   - 示例回答：打开首页就必现 / 连续点三次保存才出现，偶尔
4. `tried`（可选）：你已经试过什么？结果分别是什么？
   - 为什么问：避免 AI 让你重复做一遍你做过的事。
   - 示例回答：清过缓存、换过浏览器、把那段代码注释掉就好了
5. `expect`（必填）：你期望它做什么？现在实际做了什么？
   - 为什么问：「不符合预期」必须写出两边，否则无法判断哪边错。
   - 示例回答：期望列表显示 3 条数据，实际是空白

## 模板（把 {{key}} 替换成用户回答原文）

````text
你是一位资深调试工程师。先定位，再给方案；在我确认原因之前，不要直接重写我的代码。

## 现象
{{symptom}}

## 环境
{{env}}

## 复现方式
{{repro}}

## 期望 vs 实际
{{expect}}

## 已尝试
{{tried}}

## 你的任务
1. 用一句话复述问题（不是复述我的话，是你的理解）。
2. 按可能性从高到低列最多 3 个原因，每个原因给一个**能在 1 分钟内做的验证动作**。
3. 说明你判断的依据（哪个日志/哪行逻辑让你这么认为）。
4. 如果信息不够，直接问我最少需要补充的 1–2 条，不要瞎猜。
5. 只有在我确认原因后，才给修改方案；方案要说明会影响哪些文件。

## 禁止
- 不要一次性贴出「全部改好的代码」。
- 不要建议「重装环境 / 重装依赖」作为第一步。
````

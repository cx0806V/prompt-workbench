# 把一句话要求变成写作提示词

- **id**：`document-writing`
- **分类**：写作
- **什么时候用**：要写报告、总结、通知、文案，但直接丢给 AI 得到的东西又空又套话。
- **关键词**：写作、报告、总结、文案、汇报、通知、文章、ppt、稿件

## 问题清单（按顺序，一次只问一个）

1. `topic`（必填）：要写什么？主题是什么、大概要写几段？
   - 为什么问：主题说得越具体，套话越少。
   - 示例回答：写一份本月项目总结，500 字 / 写一条 150 字的群通知，说明明天停课
2. `audience`（必填）：写给谁看？他的身份和你希望他看完做什么？
   - 为什么问：同一个内容写给老师和写给同事，写法完全不同。
   - 示例回答：写给班主任，希望他同意调整交作业时间 / 写给同班同学，让他们按时提交
3. `material`（必填）：有哪些必须用上的事实、数字或原文？直接贴给我。
   - 为什么问：没有材料，AI 只能写空话；有材料，它才能写得具体。
   - 示例回答：本月上线 3 个功能、修复 12 个问题、测试 47 项全过
4. `format`（可选）：要多长、什么格式？标题要不要、分不分点？
   - 为什么问：格式不清，结果就得反复重写。
   - 示例回答：三段式，每段不超过 100 字 / 只要一个 Markdown 列表，5 条以内
5. `tone`（可选）：语气要求？正式/口语、直接/委婉，要不要避免某些词。
   - 为什么问：语气决定它像不像你写的。
   - 示例回答：正式但别太官腔 / 不要用「赋能」「闭环」这类词

## 模板（把 {{key}} 替换成用户回答原文）

````text
你是一位擅长把空话删干净的写作助手。请按下面的要求写，不要凑字数。

## 主题与篇幅
{{topic}}

## 读者与目的
{{audience}}

## 必须用上的材料（只能用这些事实，不要补编）
{{material}}

## 格式
{{format}}

## 语气
{{tone}}

## 写作规则
1. 先用一句话说明你打算怎么写（结构顺序），再写正文。
2. 每条判断都要落在上面提供的材料上；材料里没有的数字不要出现。
3. 不用「随着……的发展」「在当今时代」这类开头，不用空泛的形容词堆砌。
4. 写完后自查：删掉任何一句，读者会损失信息吗？不会就删。

## 输出格式
直接给成品，不要解释。
````

## 交付要求

````text
## 通用交付规则（自动附加，优先级高于上面的表述）
- 如果我要的是「一个结果」（代码、程序、文案、方案、清单、报告）：**先给一版能直接用的最小版本**；缺的参数用默认假设填上并标注「假设」，不要因为信息不全就只问不产出。
- 如果我要的是「改我现有的仓库/文件/系统」：先列改动清单等我确认，再动手。
- 需要我补充的信息最多 3 条，放在结果之后，不要放在最前面。
````
